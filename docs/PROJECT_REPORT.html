Executive Summary

The Jenkins-Based Research Paper Repository is an enterprise-grade academic publishing system engineered using Spring Boot 3.4.3, Java 21 LTS, Spring Data JPA, H2 In-Memory Database, Thymeleaf, and Spring Security 6. The system streamlines research paper submissions, real-time catalog discovery, role-based access control (RBAC), and a peer-review state machine, all continuously verified by a multi-stage Jenkins CI declarative pipeline.

All 15 development tasks spanning 4 project phases have been fully executed, tested, and validated. Automated quality assurance encompasses 79 passing tests (76 unit/integration/security slice tests and 3 headless Chrome Selenium WebDriver end-to-end tests) delivering a 100% pass rate.

1. System Architecture & Technical Specifications

The application utilizes a modular layered architecture with strict separation of concerns across presentation, security, domain service logic, and persistence.

Component Layer Technology Version Technical Rationale & Architectural Purpose
Core Runtime Java LTS (Eclipse Temurin) 21.0.12.1 Modern record patterns, virtual threads, LTS stability.
Application Framework Spring Boot 3.4.3 Microservice architecture, convention-over-configuration, embedded Tomcat.
Persistence & ORM Spring Data JPA / Hibernate 6.x Repository abstraction, automated SQL generation, transaction management.
Relational Database H2 In-Memory Database 2.3.232 Ephemeral, zero-footprint storage for rapid CI verification and isolated test states.
Security & RBAC Spring Security 6.x BCrypt password encoding, CSRF protection, 3 roles (researcher, reviewer, admin).
Web Presentation Thymeleaf + Bootstrap 5 5.3.3 Server-side HTML rendering, responsive glassmorphism UI, WCAG accessibility.
Continuous Integration Jenkins CI 2.580.1 Declarative pipeline automation: compile, test, package, and JUnit report publishing.
E2E Browser Testing Selenium WebDriver 4.28.1 Headless Chrome automated user-journey and email privacy compliance validation.
Container Packaging Docker & Docker Compose Multi-stage Standardized container build running as non-root user on Alpine/Temurin JRE.
Infrastructure Automation Ansible Playbook (deploy.yml) Declarative provisioning of server dependencies, repository cloning, and container startup.

    • reviewer (Role: REVIEWER) — Can access review queue and transition paper review states.
    • admin (Role: ADMIN) — Full administrative rights and metrics dashboard access.
    Enabled CSRF tokens on all state-mutating requests and mapped custom /login view.
  • Proof of Work: 12/12 security slice tests in SecurityConfigTest.java passed verifying role authorization.

Task 10: Peer-Review Workflow & 5-State Lifecycle State Machine

Sprint: Week 6 | User Stories: US-006, US-007 | Status: COMPLETED
  • Objective: Implement reviewer queue and enforce formal state machine transitions.
  • Implementation: Built ReviewController.java (/reviews, /reviews/, /reviews//transition). Valid transitions:
    • SUBMITTED → UNDER_REVIEW
    • UNDER_REVIEW → ACCEPTED (Terminal)
    • UNDER_REVIEW → REJECTED (Terminal)
    • UNDER_REVIEW → REVISIONS_REQUESTED
    • REVISIONS_REQUESTED → SUBMITTED (Triggered upon author edit)
    Illegal transitions throw IllegalStateException.
  • Proof of Work: 10/10 MockMvc tests in ReviewControllerTest.java and 10 state machine unit tests in PaperServiceTest.java passed.
